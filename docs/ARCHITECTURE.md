# منصة النقابة — اتفاقية المعمارية والتنفيذ

> وثيقة حية: تُحدَّث مع كل مرحلة. أي قرار جديد يُضاف في «سجل القرارات» (القسم 14) بتاريخه.
> الإصدار: 0.1 — 18 نوفمبر 2026 — الحالة: **المرحلة 0 (التصميم)**

## 1. الهدف والنطاق

بناء **منصة ERP واحدة** تخدم النقابة العامة بالدقهلية وأعضاءها وبعض الموظفين غير الأعضاء، تغطي:
الأعضاء وأسرهم · الحوكمة ومجلس الإدارة · المالية والمحاسبة · الخزينة والبنوك والشيكات · سجل المزايا الموحّد · الأنشطة (رحلات، مصايف، إفطار، فعاليات، مبادرات شراء، أجهزة بالتقسيط، منح المناسبات) · التقارير والرقابة.

**مبدأ حاكم:** كل جنيه يدخل أو يخرج أو يُعفى منه — له قيد محاسبي، ومستند مرقّم، وقرار سند، ومستفيد معروف.

## 2. ثوابت لا تُمس

1. **منظومة الكتب (`we-books`) لا تُعدَّل** خلال بناء المنصة. تبقى على رابطها الخاص المؤقت
   `https://we-books-rose.vercel.app` وschema `books` ودالة `books-api`، حتى اكتمال المنصة.
   الربط معها **قراءة فقط** عبر محوّل (Adapter) — القسم 11.
2. لا تُكتب بيانات في MyNekaba (Firestore) من المنصة. MyNekaba مصدر نقل فقط حتى يتحول للقراءة فقط.
3. نفس مشروع Supabase (`bulfwclnhbwpzqwnxjie`) — schemas جديدة منفصلة، ولا تُعدَّل `books` ولا `public` الحالية.
4. لا منطق مالي في المتصفح. المتصفح يعرض ويطلب فقط.

             محرّك الأنشطة المشترك (activities)
                         │

| Schema | المحتوى |

| `treasury` | الخزائن والبنوك، دفاتر الشيكات، الشيكات، الإيصالات (قبض/صرف)، العُهد، التسويات البنكية، تسوية الشيكات |

## 4. الأشخاص والأسر (`core`)

- **الشخص:** مفتاح داخلي UUID + الرقم القومي (فريد) + الرقم الوظيفي (إن وُجد) + الموبايل.
- **الصفة** (سجل بتاريخ بداية/نهاية): عضو جمعية عمومية · موظف غير عضو · معاش · تعهيد · زائر · مستقيل · متوفى.
- **حالة العضوية:** نشط · موقوف · إجازة بدون أجر · معاش · استقالة · وفاة — كل تغيير حركة بتاريخ وسند.
- **الأسرة:** سجل ثابت لكل فرد (الاسم، الصلة، النوع، تاريخ الميلاد، القومي اختياري). السن يُحسب تلقائياً. تستخدمها كل الأنشطة.
- **المرافق:** شخص خارج الأسرة يُسجَّل في الحجز (أو يُحفظ للاستخدام لاحقاً).

## 5. الحوكمة (`governance`)

- الدورة النقابية (من/إلى) ← الانتخابات والمرشحين والنتائج ← **تشكيل المجلس**: لكل عضو منصب (رئيس، نائب، أمين عام، أمين صندوق، عضو) بتاريخ بداية ونهاية.
- الاجتماعات ← **القرارات** (رقم، تاريخ، نص، تصنيف: صرف/دعم/إعفاء/تكليف/لائحة).
- قاعدة: «هل كان عضو مجلس يوم X؟» تُحسب من التواريخ، لا من خانة نصية.
- أي صرف أو دعم أو إعفاء أو تكليف مشرف **يشير لقرار**.

## 6. المالية (`finance`)

- **دليل حسابات** هرمي (أصول، خصوم، إيرادات، مصروفات، صناديق) — يُعتمد في المرحلة 3.
- **قيد مزدوج:** كل عملية في أي وحدة تولّد قيداً متوازناً تلقائياً. قاعدة البيانات ترفض قيداً غير متوازن.
- **السنة والفترات:** فترة مقفولة لا تُعدَّل؛ التصحيح بقيد عكسي فقط.
- **مراكز التكلفة:** كل نشاط/مبادرة مركز تكلفة ← ربحية وتكلفة كل نشاط.
- **الموازنة:** بنود معتمدة سنوياً، وتنبيه عند الاقتراب من الحد.

## 7. الخزينة والشيكات (`treasury`)

- دفاتر الشيكات وأرقامها (فريدة بقيد في قاعدة البيانات).
- **الشيك مربوط** بقرار + نشاط/مركز تكلفة + مستفيد (لا نص حر).
- إيصالات قبض/صرف بترقيم بلا فجوات.
- **تسوية الشيك:**
  `الرصيد = الشيك + الاشتراكات − (المصروفات + الإعفاءات + الاستردادات)`
  - فائض ← **رد للخزينة** أو **توريد للبنك** بمستند (إيصال/إشعار إيداع) — قرار 18 نوفمبر.
  - عجز ← لا تُقفل التسوية إلا بقرار تغطية.
- العُهد، والتسوية البنكية الشهرية.

## 8. سجل المزايا الموحّد (`benefits`)

كل ميزة لأي شخص من أي وحدة = حركة واحدة:

| الحقل | المعنى |
|---|---|
| person | المستفيد |
| source_module | books / trips / resorts / iftar / grants / devices / board / … |
| source_ref | المرجع (حجز، طلب منحة، تكليف) |
| kind | دعم · إعفاء كلي/جزئي · خصم · بدل · منحة · ميزة عينية · تقسيط بلا فوائد |
| amount | القيمة النقدية المكافئة |
| basis | السند (قرار/شيك/فاتورة) |
| capacity | الصفة وقتها (عضو / عضو مجلس + المنصب) |
| status | فعّالة · ملغاة (بحركة عكسية) |

- **إعفاء المشرف** يُحسب بالسعر الكامل لفئته ويُسجَّل «إعفاء مشرف — ميزة نقدية».
- ملف العضو: «استفاداتي» بالسنة والمبادرة. تقرير «مزايا أعضاء المجلس» بالاسم والمبلغ والسند.
- **سقف الاستقطاع من الراتب:** إعداد سنوي مرن، وتجاوز فردي بسبب مكتوب — يشمل كل الوحدات.

## 9. الهوية والصلاحيات

| الدور | النطاق |
|---|---|
| عضو جمعية عمومية | بوابته، الحجز، حسابه، استفاداته، طلب المنح |
| موظف غير عضو | الأنشطة المسموح بها لفئته فقط، بلا دعم |
| عضو مجلس إدارة | كالعضو + اعتمادات وتقارير حسب منصبه |
| أمين الصندوق | الخزينة، الشيكات، التحصيل، الاعتماد المالي |
| مسئول رحلات/مصايف/فعاليات | إدارة أنشطته، تسجيل المصروفات (بلا اعتماد نهائي) |
| مسئول أجهزة التقسيط | الأجهزة والأقساط والاستقطاع |
| مدير المنظومة | الإعدادات والمستخدمين والصلاحيات |
| مراجع (اختياري) | قراءة كاملة + سجل التدقيق |

- **فصل المهام:** المسجِّل ≠ المعتمِد ≠ الصارف.
- الصلاحية = (وحدة × عملية × حد مالي). مثال: اعتماد صرف حتى 5000، وما فوقه لرئيس المجلس.
- RLS على كل جدول؛ لا جدول معروض للعامة.

## 10. محرّك الأنشطة (`activities`)

**نشاط = نوع + نموذج + إعدادات.** نوع جديد = نموذج جديد، لا برنامج جديد.

### 10.1 ملف النشاط (كل قسم يُفعَّل حسب النوع)
1. البيانات والحالة: مسودة ← معتمد ← الحجز مفتوح ← مقفول ← جاري ← انتهى ← سُوّي ← مغلق.
2. البرنامج (يوم/ساعة) والملاحظات.
3. **الأهلية والفئات والأسعار:** فئات حرة لكل نشاط (عضو، زوج، طفل حسب سن **يُحدد لكل نشاط**، مرافق…)، لكل فئة سعر ودعم وحد أقصى.
4. **السعة والحدود:** الحد الأقصى للمشاركين/المرافقين **إعداد للإدارة لكل نشاط**.
5. **التوزيع:** أسبقية (بوقت تأكيد الدفع) · قرعة موثّقة · أولوية (لم يستفد سابقاً) · مزيج.
6. **الانتظار والتصعيد** بمهلة تأكيد للمُصعَّد.
7. **الدفع:** كاش · تقسيط · استقطاع من الراتب — كل نشاط يحدد المتاح وشروطه.
8. **الإلغاء والاسترداد:** شرائح لكل نشاط («قبل X يوم ← Y%»، بديل من الانتظار ← كامل، غياب بلا إلغاء ← لا استرداد ولا دعم). **الشروط تُجمَّد في الحجز وقت الحجز.** إلغاء النشاط كله ← استرداد جماعي.
9. **الموارد والتسكين:** أتوبيسات وكراسي · وحدات وأفواج · غرف · موائد.
10. **المشرفون:** بقرار تكليف، ونسبة إعفاء/دعم لكل مشرف وأسرته، وحد أقصى لعدد المشرفين.
11. **الدفتر والتسوية:** الشيك، المصروفات بمستنداتها، الإيرادات، التسوية.
12. **التواصل:** جروب واتساب، رسائل جاهزة، إعلانات داخل التطبيق.
13. **المستندات:** عقود، فواتير، صور، باسبورات/تأشيرات (للعمرة والحج).
14. **الحضور:** QR عند الركوب/الدخول.
15. سجل التعديلات.

### 10.2 الأنواع المخططة
| النوع | خصائص مميزة |
|---|---|
| رحلة يوم واحد | دعم بشيك، أتوبيس وكراسي |
| رحلة بإقامة | غرف وتسكين |
| عمرة / حج | بلا دعم، تقسيط طويل، مستندات وتأشيرات، شركة سياحة بحساب |
| مصيف | مواسم مرنة تختلف كل سنة، وحدات × أفواج، أسبقية/قرعة، **اعتذارات وتصعيدات وتبديلات** (فوج/وحدة/بين أعضاء بموافقة)، محضر تسليم وتأمين |
| إفطار مجمّع | موائد، QR دخول، دعم كامل غالباً |
| فعالية/مسابقة/دورة | حضور وشهادات وجوائز |
| مبادرة شراء | أصناف بكميات (نموذج الكتب) |
| أجهزة بالتقسيط | معرض متعاقد، تقسيط واستقطاع |
| منح المناسبات | طلب بمستند ← اعتماد ← صرف (زواج، مولود، وفاة، تفوق، علاج) |
| خدمة متعاقدة | خصم لدى جهة (نادي/مستشفى) بكود يُسجَّل |

### 10.3 تجربة العضو
دخول واحد ← «أنشطتي» (كروت حسب صفته) ← كل نشاط بواجهته (الكتب = البوابة الحالية، الرحلات = تطبيق رحلات…) مع شريط تنقل ثابت ← «حسابي الموحّد» (لي/علي في كل الأنشطة) ← «استفاداتي» ← الإشعارات.

### 10.4 تجربة الإدارة
لوحة واحدة: الأنشطة الجارية، الخزينة، **اعتمادات منتظرة**، التنبيهات (موازنة/أقساط/شيكات غير مسوّاة). كل مسئول يرى وحدته فقط.

## 11. الربط مع منظومة الكتب (قراءة فقط)

- **محوّل `books_adapter`:** view/وظيفة في schema المنصة تقرأ من `books.records` (بلا كتابة)، وتنتج:
  1. حركات «خصم» في سجل المزايا (التوفير لكل فاتورة).
  2. قيوداً محاسبية مجمّعة لتحصيلات ومدفوعات المبادرة (مركز تكلفة «الكتب»).
- **الدخول:** مؤقتاً كارت «الكتب» في «أنشطتي» يفتح الرابط الحالي. الدخول الموحّد الكامل يُقرر بعد اكتمال المنصة.
- أي تعديل في الكتب نفسها بطلب صريح فقط وفي مستودعها.

## 12. النقل من MyNekaba

**المصدر:** ملف النسخة الاحتياطية الكامل من «مركز النسخ الاحتياطي» في MyNekaba (JSON لكل المجموعات) — لا يحتاج مفاتيح سرية.

المجموعات: employees · member_movements · board_terms · board_memberships · board_meetings · board_candidates · board_movements · board_benefits · events · event_bookings · member_benefits · issued_checks · checkbooks · transactions · settings · …

**خطوات النقل:**
1. **لقطة خام** في `legacy` كما هي.
2. **تحويل ونظافة:** توحيد الأشخاص بالرقم القومي/الوظيفي (لا بالاسم) · ربط الشيك بالنشاط · دمج المزايا من (member_benefits + board_benefits + issued_checks) بلا تكرار · حركات الخزينة ← قيود · status مكرر ← حقل واحد.
3. **تقرير مطابقة** يعتمده المستخدم: أرصدة الخزينة/البنك قبل وبعد بالقرش، عدد الأعضاء، إجمالي المزايا لكل عضو، قائمة استثناءات.
4. **رصيد افتتاحي** بتاريخ القطع + أرشيف للاستعلام.
5. **تشغيل متوازٍ** ثم MyNekaba قراءة فقط.

**ملاحظات من مراجعة MyNekaba (18 نوفمبر):** حساب الأسعار والمبالغ في المتصفح بلا تحقق · عدّاد الحجز يُكتب من المتصفح (حجز زائد ممكن) · الإلغاء بلا استرداد مسجّل · المزايا في 3 أماكن · الشيك مرتبط بالنشاط بنص حر · مساران مختلفان للحجز · لا أسبقية/قرعة/انتظار/استقطاع · لا قائمة أسرة ثابتة. يُستفاد من: أنواع الأنشطة الموصوفة بإعدادات، لقطة حالة العضو في كل سجل، وسوم مصدر المزايا، المعرّفات الثابتة للجوائز.

## 13. التقنية والمعايير

- **قاعدة البيانات:** Postgres (Supabase) بقيود حقيقية (FK, CHECK, UNIQUE)، ومشغّلات للقيد المتوازن وقفل الفترات والسعة.
- **الخادم:** Edge Function `erp-api` بعقد `call(action, payload)` (نفس فلسفة الكتب)، كل عملية مالية داخل transaction واحدة.
- **الواجهة:** ملفات ثابتة خفيفة على Vercel (نفس نهج الكتب: سريعة على الموبايل الضعيف، عربية RTL، تعمل أوفلاين للعرض).
- **المبالغ:** `numeric(14,2)` — لا float.
- **الترقيم:** عدادات بلا فجوات لكل نوع مستند وسنة.
- **الاختبارات:** سيناريوهات آلية لكل وحدة قبل أي دمج.
- **النسخ الاحتياطي:** لقطة ليلية + تصدير يدوي.
- **رسائل الـ commit بالعربية**، والعمل على فروع ثم دمج.
- **الاستهلاك:** الخطة المجانية — ضغط الردود وبصمات البيانات من البداية.
